# Workout Maker

Hyper-personalized **running + strength** workouts, generated by the LLM of
your choice and synced bidirectionally to your **Amazfit watch** via
**Intervals.icu**. One shared Supabase backend powers both a **Next.js web app**
and a **Kotlin / Jetpack Compose Android app**.

Everything runs on **free tiers, forever** — you bring your own LLM and
Intervals.icu keys; there are no platform-level API costs.

```
┌────────────┐     ┌───────────────────────────┐     ┌──────────────┐
│  Web (PWA) │     │        Supabase           │     │ Android (APK)│
│  Next.js   │◀───▶│  Postgres + Auth + RLS    │◀───▶│  Compose     │
│  Vercel    │     │  Edge Functions (Deno)    │     │  Hilt/Room   │
└────────────┘     │  Realtime + pg_cron       │     └──────────────┘
                   └────────────┬──────────────┘
                                │  (server-side only)
                  ┌─────────────┴─────────────┐
                  ▼                           ▼
          Intervals.icu API            LLM providers
        (Zepp ⇄ watch bridge)   (Anthropic/DeepSeek/OpenAI/
                                    Gemini/Groq — user keys)
```

## Monorepo layout

| Path                 | What                                                        |
|----------------------|------------------------------------------------------------|
| `supabase/migrations`| Schema, RLS, exercise library, crypto RPCs, cron           |
| `supabase/functions` | 14 Deno Edge Functions + shared `_shared/` modules         |
| `supabase/seed.sql`  | One sample athlete with 30 days of training history        |
| `web`                | Next.js 14 app (App Router, Tailwind, shadcn-style, Recharts)|
| `android`            | Android Studio project (Compose, Hilt, Supabase SDK, Room) |
| `shared`             | Canonical TypeScript types shared by web + (mirrored) Android |

## Multi-LLM provider system

A single `llmGenerate(provider, { prompt, systemPrompt, apiKey })`
(`supabase/functions/_shared/llm.ts`) normalizes requests/responses across:

| Provider  | Model                    | Notes                |
|-----------|--------------------------|----------------------|
| Anthropic | claude-sonnet-4-20250514 | Best reasoning       |
| DeepSeek  | deepseek-chat            | Very cheap           |
| OpenAI    | gpt-4o-mini              | Balanced             |
| Gemini    | gemini-2.0-flash         | **Free tier**        |
| Groq      | llama-3.3-70b-versatile  | **Free tier**, fast  |

The same system prompt (with an embedded JSON schema) is sent to every
provider. On failure, `llmGenerateWithFallback` walks the user's configured
fallback chain. Every call is recorded in `generation_logs` (provider, tokens,
cost, prompt, raw response) — viewable in the app's **Generation History**.

API keys (LLM + Intervals.icu) are encrypted at rest with **pgcrypto**; the
symmetric key lives only in the `ENCRYPTION_KEY` Edge Function secret, never in
the database or any client.

## 1. Supabase — local dev & free-tier deploy

### Prerequisites
- [Supabase CLI](https://supabase.com/docs/guides/cli) and Docker.

### Local
```bash
supabase start                       # boots Postgres+Auth+Realtime+Studio
                                     # applies migrations + seed.sql automatically
cp supabase/functions/.env.example supabase/functions/.env   # set ENCRYPTION_KEY
supabase functions serve --env-file supabase/functions/.env
```
Studio: http://localhost:54323 · API: http://localhost:54321
Seeded login: **athlete@example.com / password123**

### Deploy to the free cloud tier
```bash
supabase login
supabase link --project-ref YOUR-PROJECT-REF

# 1) schema + seed
supabase db push                     # runs everything in supabase/migrations

# 2) the only secret you must set
openssl rand -base64 48 | xargs -I{} supabase secrets set ENCRYPTION_KEY="{}"

# 3) functions
supabase functions deploy            # deploys all functions

# 4) enable the 30-min sync cron (one-time, run in the SQL editor):
#    alter database postgres set "app.functions_base_url" = 'https://YOUR-REF.functions.supabase.co';
#    alter database postgres set "app.service_role_key"   = 'YOUR-SERVICE-ROLE-KEY';
```

### Edge Functions
| Function            | Purpose                                                     |
|---------------------|-------------------------------------------------------------|
| `connect-intervals` | Verify + encrypt-store Intervals.icu creds                  |
| `sync-intervals`    | Cache activities + CTL/ATL/TSB (cron every 30 min)          |
| `generate-workout`  | Full AI generation flow → planned_workouts → Intervals push |
| `plan-week`         | Periodized 7-day microcycle in one shot (also the auto-plan cron) |
| `plan-block`        | Multi-week periodized block toward the goal race            |
| `coach-chat`        | Agentic coach: native tool calling + SSE streaming          |
| `push-workout`      | Push an existing plan to the Intervals.icu calendar         |
| `push-strength`     | Push a logged strength session to Intervals.icu             |
| `delete-workout`    | Delete a plan + its Intervals.icu/watch event               |
| `schedule-template` | Schedule a saved workout template onto the calendar         |
| `refresh-memory`    | Maintain the rolling athlete "training memory"              |
| `intervals-stats`   | Live Intervals.icu physiology (zones, thresholds)           |
| `test-llm-key`      | Validate a provider key with a minimal call                 |
| `daily-summary`     | Readiness score + dashboard payload                         |

Unit tests live next to the shared modules (`_shared/*_test.ts`):
```bash
cd supabase/functions && deno test _shared/
```

## 2. Web app → Vercel (one command)

```bash
cd web
cp .env.example .env.local           # fill in NEXT_PUBLIC_SUPABASE_* 
npm install
npm run dev                          # http://localhost:3000
```

Deploy:
```bash
npm i -g vercel
vercel                               # first run links the project
vercel --prod                        # one-command production deploy
```
Set `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` in the
Vercel project settings. The app ships a PWA manifest, so it's installable.

## 3. Android — build & sideload the APK

```bash
cd android
# point the build at your Supabase project (anon-safe values):
cat >> local.properties <<EOF
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_ANON_KEY=YOUR-ANON-KEY
EOF

./gradlew assembleRelease            # → app/build/outputs/apk/release/app-release.apk
adb install app/build/outputs/apk/release/app-release.apk   # or sideload manually
```
Open in **Android Studio** for the smoothest experience (it provisions the
Android SDK automatically). Distribute the APK via **GitHub Releases**.

Bottom nav: **Home · Calendar · Strength · Settings**. WorkManager fires a
daily 7 am wellness check-in reminder; Room caches data for offline-first use.

## 4. Get free API keys (zero cost to start)

Start with a **free-tier** provider and you'll never pay:

- **Groq** — https://console.groq.com/keys (free, very fast Llama 3.3 70B)
- **Gemini** — https://aistudio.google.com/app/apikey (generous free tier)

Paste the key in **Settings → LLM** (or during onboarding step 3), hit
**Save & Test**, set it active, and generate your first workout.

Other providers (Anthropic, OpenAI, DeepSeek) work the same way — add a key and
order your fallback chain however you like.

## How a workout is generated

1. Pull profile, last 14 d activities, last 7 d wellness, CTL/ATL/TSB.
2. Decide type (avoid back-to-back hard days; enforce 48 h muscle recovery).
3. Build a context-rich prompt (HR zones, TSB interpretation, 10% volume rule,
   working weights, soreness…).
4. Call the active provider; fall back down the chain on error.
5. Parse + validate JSON against the workout schema.
6. Save to `planned_workouts`, log to `generation_logs`, push to Intervals.icu →
   which syncs to your Amazfit watch.

## Security notes
- **RLS** on every table — users only ever see their own rows.
- Secrets encrypted with pgcrypto; `ENCRYPTION_KEY` is an Edge Function secret.
- Intervals.icu + LLM keys are used **server-side only** inside Edge Functions.
